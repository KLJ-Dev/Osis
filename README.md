# 🌊 OSIS.DI

**공공기관 및 외부 서비스의 데이터를 수집·변환·전송하는 C# 기반 데이터 연동 프로젝트**

OSIS.DI의 DI는 **Data Integration**을 의미합니다.

기존에 개발한 OSIS의 NHIS 연동 기능을 공개용으로 정리하고, 업무 정의와 실행 로직을 분리하는 구조 개선 과정을 기록합니다.

> 현재 단계: 공개용 소스 정리 및 구조 개선 준비  
> 소스코드와 검증 결과는 정리 후 순차적으로 공개합니다.

<br />

## 📃 프로젝트 정보

### 1. 개발 형태

개인 프로젝트 — 기존 OSIS 기반의 공개용 프로젝트 구성 및 리팩터링

### 2. 담당 범위

- 공공기관 데이터 연동 로직 개발

NHIS 연동 기능과 실행에 필요한 공통 모듈을 우선 공개합니다. 다른 기관의 연동 코드는 이번 공개 범위에 포함하지 않습니다.

## 📊 시스템 구조

### 개선 방향

기관별 파라미터와 업무 순서를 **정의 모듈**에서 관리하고, **공통 실행기**가 해당 정의를 해석하여 실행하도록 개선할 계획입니다.

| 구성요소 | 역할 |
| :--- | :--- |
| Param | 업무별 입력 파라미터와 검증 규칙 정의 |
| Workflow | 요청 매핑 및 단계별 실행 순서 정의 |
| WorkflowRunner | 정의된 단계 실행 및 오류 처리 |
| RunContext | 요청별 입력값·쿠키·중간 결과 관리 |

> 위 구성은 개선 목표입니다. 실제 구현에 맞춰 UML 클래스·시퀀스 다이어그램을 추가할 예정입니다.

아래는 기존 OSIS에서 다루는 기능입니다. 공개용 소스 정리 후 해당 코드와 실행 예제를 연결합니다.

- 인증서 선택 화면
- 기관 연동에 필요한 인증 관련 처리

- 런처를 통한 프로그램 실행
- DLL 기반 기능 모듈 구성

## 🛠️ 구조 개선 및 문제 해결

### 1. 파라미터와 요청 매핑 중앙화

**기존 문제**

업무 입력값과 요청 문자열의 매핑이 실행 코드에 섞여 있어, 변경 시 여러 위치를 확인해야 합니다.

**개선 계획**

업무별 `Param`과 `Workflow`에 입력 규칙과 요청 매핑을 모으고, 실행 로직에서 참조하도록 변경합니다.

**검증 계획**

`WETC_110`의 요청 매핑부터 개선하고, 동일한 예제 입력에 대해 기존 코드와 개선 코드가 생성한 요청 데이터를 비교합니다.

### 2. 업무 정의와 실행 로직 분리

**기존 문제**

기관별 업무 순서와 통신 처리가 결합되어 있어, 업무 추가·변경 시 실행 코드의 수정 범위가 커집니다.

**개선 계획**

기관별 정의 모듈과 공통 실행기를 분리하고, 실행기가 지원하는 단계 조합으로 업무를 구성합니다.

기존 단계의 순서·파라미터·매핑 변경은 정의 모듈에서 처리하고, 새로운 인증 방식이나 처리 기능이 필요한 경우 실행기를 확장합니다.

### 3. 빌드·테스트 및 배포 자동화

**개선 계획**

GitHub Actions를 이용한 빌드·테스트 자동화를 구성하고, 배포 방식 확정 후 릴리스 자동화를 연결합니다.

> 각 개선 항목은 구현과 검증을 완료한 뒤 결과를 갱신하고, 관련 코드·Issue·Pull Request를 연결합니다.
